# 所有流程步骤统一为状态插件

更新：2026-11-18。本文为设计契约；M05 已实现标准状态链与扩展示例，具体边界见 [M05](m05-workflow.md)。准备、执行、事实审核、人工验收、完成都实现同一个 State，不另设通用审核引擎或交付检查列表。

## 接口与状态上下文

| 方法 | 语义 |
| --- | --- |
| Describe | 稳定 key、角色、规则版本、行为配置摘要；不含凭据 |
| CheckEnter | 只读判断当前证据能否进入，返回 allow/wait/reject 和原因 |
| Enter | 本地幂等准备/同步该步骤记录，可重复；不得远端 IO |
| CheckComplete | 只读判断该步骤针对当前轮及当前证据是否完成，附证据版本 |

调用包含可信主体/父 CommandID、事务、TaskID、FlowRef、RoundID、EntryID、当前依据及候选引用。状态自行通过 Deps 读取所需事实；不接收客户端自述“审核已过”。Enter 幂等键包含 EntryID 及所处理的证据组合，不能仅以曾经进入过为由沿用旧结论。没有独立 Reconciler/Coordinator 接口。

准备负责信息/阻塞/依赖就绪，执行负责有效执行/交付，事实审核负责其证据要求，人工验收负责当前评审记录和决定，完成负责目标/结果/必要子任务完整性。需要什么能力由各步骤 Deps 明确声明；检查算法可以是普通内部函数，不要求每个条件又注册插件。

## 顺序推进与证据变化

1. CreateTask 同事务创建事实和策略，Initialize 分配首 RoundID/EntryID 并进入首步骤；默认准备步骤允许信息不齐可见。
2. 命令更新事实后 Evaluate。对本轮已到达的步骤按顺序幂等调用 Enter 同步当前证据，然后只读检查；未到达步骤不得提前产生进入副作用。旧步骤结论不满足当前证据时保留当前位置，报告具体阻塞步骤，不自动倒退、不默许继续。
3. 已到达前序步骤和当前步骤均完成，下一步骤允许进入且固定保护通过，写新位置/EntryID 并调用 Enter。所有本地动作同事务，技术失败回滚。
4. 进入终态前重新校验全部已到达步骤的当前证据、完成步骤条件及执行安全退出。所有证据版本纳入锁/校验，不能把曾经通过当成永久通过。
5. 达到单次推进上限写 continuation outbox，返回明确待继续；业务等待不忙循环。后台/手工核对复用同一算法，终态不自动重开。

这使“先事实审核后人工验收”在补交结果时仍正确：前序审核记录按新 SubmissionID 失效/重建，旧人工通过也失效；可在原位置等待新的前序证据，或由用户显式 Return 开新轮。旧轮历史永不覆盖。新候选出现时即使审核等待，命令仍应同步所有已到达步骤以撤销旧当前结论，再判断是否允许推进。

## 人工输入与远端工作

人工验收插件可额外提供 acceptance.Actions.RecordVerdict 事务内能力。验收命令校验身份/版本后调用它，再调用 flow.Evaluate；状态插件不依赖该命令或 flow，避免环。事实审核若只读本地材料无需专门写服务；若需要外部结论，可拥有自己的记录接口及命名动作/API，记录完成后同样核对。

Enter 只建立本地待办/outbox，不运行模型/工具或请求远端审核。同一证据组合多次 Evaluate 不重复请求；更换候选后旧远端回执只能记录历史，不覆盖新候选。事件接收不等于审核通过。

## 提交与取消/退回

提交格式/内容合法性、权限、执行代次、轮次及依据由命令和事实模块校验，是登记前条件。事实审核/人工验收是登记后的流程步骤：失败或等待保留已提交结果，不把流程拒绝当成数据库错误回滚。任一技术错误仍整体回滚，保留 C13。

Cancel 立即取消及失效写入代次，保留外部停止待确认。Return 只能到定义声明的较早步骤，Reopen 仅终态进入定义 reopenState；两者在停止保护通过后新建轮次。Retry/Replace 同轮换执行先安全退出。普通 Wake/Evaluate 不重开终态。

认领不能因为过去通过准备步骤而绕过新阻塞：执行命令先通过流程的 CheckAction(OpenExecution) 只读重查已到达步骤及当前步骤的 CheckEnter，并结合 Describe 的可执行角色，再认领。它不是通用 Execute，不能写状态或授权任意动作。准备在认领前完成即可允许进入执行，执行 CheckEnter 不以已经认领为前提，防止自锁。完成再检查权威子任务/依赖，第二阶段相应步骤替换/配置依赖读取能力。

## 定义与单一目录

目录唯一接收 flows 列表并发布定义，API/命令/worker 只依赖目录接口；状态不反向依赖目录。定义保留状态顺序及行为版本，验收要求由人工验收步骤的描述派生，非额外 acceptanceMode 开关。部署配置改变不能修改旧 FlowRef。

```yaml
# 设计片段，尚不可运行；其余必要 Deps 在清单中。
flow.standard:
  use: task/flow
  deps:
    states:
      - use: state/ready
      - use: state/executing
      - use: state/fact-review
      - use: state/accepting
      - use: state/completed
```

可省略事实审核，或省略人工验收；授权/依据/执行安全保护不随之消失。此片段不替代真实配置，实际构建必须补齐各步骤的 Deps 并检验角色/顺序/owner。
