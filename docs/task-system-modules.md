# 任务系统模块划分与功能参考

日期：2026 年 11 月 17 日。

本文依据当前已确认的项目范围和模块讨论，作为后续模块设计与开发的功能参考。模块是业务职责划分，不预设服务、进程、仓库或数据库的拆分。具体状态、默认策略及接口契约仍需在模块设计时确定，不将本文中的功能清单直接等同于全部首版交付承诺。

插件能力接口、Config、Deps 及 SQL/S3 存储边界见[插件契约草案](plugin-contracts.md)，完整装配见[base](../base.yaml)，日常维护见[config](../config.yaml)，两层合并与流程示例见[配置说明](configuration.md)。

## 项目范围与基本关系

本项目只建设任务系统。软件分发与管理平台、Agent 执行层复用已有能力，通过接口对接。

- 人是任务的默认负责人，对任务推进、关键决策和最终交付负责。
- Agent（Buddy）是任务执行者；规划、协调、审查等也是可授权给 Buddy 的职责，不等于任务负责人。
- 执行实例是 Buddy 某次运行所在的具体实例，记录在执行记录中。
- 更换执行 Buddy 或运行实例，不自动改变人的负责人；转交负责人是单独的业务操作。
- 任务状态表示业务进展，不能直接等同于某次 Agent 运行状态。

任务流转通过有序状态子插件和 Hook 组装：领域插件保存事实，Hook 触发检查，task/flow 统一提交状态；详见[流转契约](task-flow-plugins.md)。

## 1. 任务管理

**职责：定义要做什么、谁负责，维护任务的当前业务事实。**

需要提供：

- 创建、编辑、查看任务，支持脱离项目独立存在。
- 管理标题、目标、背景、输入材料、验收标准、优先级和期限。
- 设置人的负责人、协作者及验收者。
- 管理待处理、执行中、等待、待验收、完成、取消等业务状态，具体状态及转换规则另行确定。
- 支持重开、归档，以及按负责人、状态、期限等查询。

边界：执行是否成功、是否已有交付、是否通过验收由相应记录表达，任务信息管理不直接写状态；task/flow 按状态子插件的检查结果统一更新状态。

## 2. 任务会话与决策

**职责：记录每个任务中人与 Buddy 的协作过程，以及需要正式处理的问题和决定。**

需要提供：

- 每任务独立会话，支持文本、附件、引用回复、提及和消息编辑记录。
- 区分人的发言、Buddy 发言和系统业务事件。
- 关联目标修改、分配、交付、验收等正式操作。
- 创建结构化提问和决策请求，记录回答人、处理状态与结论。
- 区分阻塞问题和不影响继续执行的问题。

边界：普通讨论不自动改变正式业务事实。例如“建议改目标”不会直接修改目标；正式操作仍由对应模块校验和执行。

## 3. 任务树与计划

**职责：组织目标分解、协作分工和任务前后关系。**

需要提供：

- 创建子任务、多层分解、调整顺序和移动节点。
- 每个子任务保留独立负责人、执行 Buddy、会话和交付。
- 管理任务依赖，按明确条件判断前置条件是否满足。
- 批量提交一次计划调整，完整展示涉及的节点和关系变化。
- 汇总子任务进展、阻塞项和待决策项。
- 定义父子任务取消、重开、替换的影响，防止父子环和阻塞依赖环。

边界：父任务完成需要自身的交付与完成判断，不能仅凭子任务完成数量自动认定目标达成。执行端内部步骤与正式计划的界限需在设计中明确。

## 4. 分配与执行协同

**职责：将任务交给 Buddy，并维护任务侧的执行事实。**

需要提供：

- 为任务选择执行 Buddy，支持按人的负责人默认路由。
- 记录待接受、已接受、拒绝及无法执行的原因。
- 将任务分配、会话、决策、依赖及状态变化通过 WebSocket 通知授权客户端；已有 Agent 层通过 steer 自主按需读取和处理。
- 记录每次执行的 Buddy、实例、依据版本、进度和结束原因。
- 管理当前有效执行，防止旧执行覆盖当前结果。
- 支持停止请求、重试、更换执行 Buddy，以及断线后的状态核对。
- 展示人的负责人、当前执行 Buddy 及执行异常情况。

边界：进程运行、模型与工具调用、Agent 上下文恢复由已有 Agent 层负责。任务执行与 Agent 运行的对应关系，以及租约、心跳、重试、取消、恢复的权威归属，应先核对已有接口，避免重复建设执行调度。任务系统记录取消请求和停止确认，不将请求发出等同于工具已经停止。

## 5. 交付与验收

**职责：管理正式结果，并按配置判断任务是否达到完成条件。**

需要提供：

- 默认将 Agent 的结果回复登记为交付，可包含文本、文件版本引用和链接；内容复用任务会话。
- 普通交流、问题、进度不自动交付；特殊任务可通过检查子插件要求额外证据或逐项标准回应。
- 轻量交付记录固定回复修订、材料版本和需求依据；保存多次提交及撤回，不复制正文。
- 支持无需独立验收、指定验收者两种基本方式。
- 支持通过、退回修改和再次提交。
- 记录验收意见，绑定具体交付、回复修订及验收标准版本，消息编辑不改写旧证据。
- 明确无独立验收时的完成条件与判定主体。

边界：会话拥有正文，材料插件拥有文件，交付插件登记结果引用，验收插件保存结论；详见[结果回复交付](reply-delivery.md)。执行成功、已经交付、验收通过、任务完成是不同事实。复杂会签和多级验收是否进入首版另行决定。

## 6. 版本与变更

**职责：解释任务当前状态如何形成，并保留变更前后的业务依据。**

需要提供：

- 保存目标、验收标准、正式计划、分配等变更。
- 查看前后差异、操作者、原因和时间。
- 查看历史任务树和节点内容。
- 将交付、验收关联到对应需求版本。
- 提示并发修改冲突，避免静默覆盖。
- 将恢复历史内容记录为新变更，保留中间历史。
- 标记可能因上游变化而过期的执行和结果，记录重新评估的决定。

边界：业务修订、交付版本与运行事件应有明确关联，但不要求所有事件生成同一种版本。恢复范围及变更期间执行如何处理需明确；恢复内容不会撤销外部工具副作用。不预设 Git 存储或完整分支合并能力。

## 7. 身份、权限与审计

**职责：控制谁可以读取和操作哪些任务事实，并记录操作依据。**

需要提供：

- 引用已有系统的企业、成员、Buddy 和实例身份。
- 管理项目、任务树和单任务的访问范围。
- 分别授权阅读、执行、拆解、分配、修改目标、验收等操作。
- 支持直接执行、需要确认、只能提建议等条件。
- 管理 Buddy 与人的代理关系，记录实际操作者和代理归属。
- 控制任务移动、邀请参与者、历史与产物访问。
- 保存正式操作和授权变更的审计记录。

边界：身份来源复用已有能力，任务系统负责自身业务授权。人的负责人身份不使其 Buddy 自动继承全部权限。权限继承、冲突、撤销及执行验收分离规则需明确。

## 8. 工作台与通知

**职责：让人和 Buddy 找到当前需要处理的工作。**

需要提供：

- 查看本人负责、参与、待确认及待验收任务。
- 查看 Buddy 正在执行、异常和等待中的任务。
- 项目与任务树视图、搜索和筛选。
- 未读、提及、分配、决策请求、交付及验收通知。
- 期限提醒和等待超时提醒。
- 从通知直接进入对应任务、问题或交付。

边界：待办本身保存在对应业务模块，通知只负责提醒；通知丢失或已读不能使业务事项消失。所有视图、搜索和通知均受访问权限约束。

## 9. 材料与产物

**职责：保证任务输入和交付内容可访问、可追溯。**

需要提供：

- 上传、管理任务输入、附件及交付文件。
- 支持外部资源引用，标明来源与可用性。
- 控制材料读取权限和下载访问。
- 保存必要的内容版本或快照，避免历史交付随外部文件变化。
- 支持子任务引用上游材料和产物。
- 管理保留、删除、失效与导出。

边界：可以复用已有文件存储；任务系统仍须定义文件的业务归属、版本和访问规则。交付记录由交付与验收模块维护，材料模块维护其引用的内容。引用关系不自动授予读取权限。

## 10. 接口与事件对接

**职责：作为横跨业务模块的对接层，让界面、Buddy 和外部系统可靠协作。**

需要提供：

- 面向 UI、Buddy 和外部系统的业务 API。
- 对接已有身份、Buddy 注册及可用性信息。
- 前端和 Agent 共用模块化业务 API；WebSocket 推送任务变化，客户端按需读取详情、差异、消息和历史，不设置专用 Agent 上下文组装。
- 接收进度、问题、交付及停止确认。
- 支持事件订阅、增量同步、重连补拉和重复请求去重。
- 提供鉴权、接口版本、错误语义与兼容规则。

边界：接口层不另建一套业务规则。来自界面、Buddy 或外部系统的操作，应进入同一套任务、权限和版本逻辑。具体 HTTP API 模块、WebSocket、重放范围及失败处理见[通信契约](shared-api-and-realtime.md)。

## 模块协作与开发参考

存储作为共享基础模块，通过插件提供 SQL 与 S3 能力：SQL 保存任务、消息、关系、执行、版本、交付验收、权限、审计和事件；S3 保存附件与产物内容。领域插件只依赖小接口，通过配置注入存储实例。跨业务插件写入共享 SQL 事务；SQL 与 S3 通过明确的上传、可用、删除状态及补偿清理保持一致，不能假定跨存储原子提交。

基本业务闭环：人创建并负责 → 分配 Buddy → Buddy 执行并在会话中协作 → 提交交付 → 按规则完成或由人验收。

- 任务管理保存当前业务事实；会话记录协作过程，版本模块记录正式变更。
- 任务树组织分工和依赖；分配与执行协同记录执行归属，已有 Agent 层通过 WebSocket 感知变化并经共用 API 处理工作。
- 交付与验收管理结果及结论；材料与产物管理其引用的内容。
- 权限与审计贯穿所有模块；工作台和通知聚合待处理事项；接口层提供一致的对外访问。

后续开发应先打通上述基本闭环，并从开始就纳入必要的授权、变更记录和可靠同步。任务树、复杂计划和验收能力逐步扩展；每阶段的具体交付范围另行确定。

各模块设计至少需明确：对象及权威数据归属、正式操作、状态转换、权限、版本关联、事件，以及与已有系统的接口分工。优先解决执行对接、负责人和执行者关系、触发规则、完成与依赖条件、版本语义，避免在核心规则未定时固化数据模型。
