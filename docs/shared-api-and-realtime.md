# 共用 API 与授权变化流

M04/M05 已实现认证、业务 HTTP API 和受权变化补拉（见 [M04](m04-workspace.md)）；WS 协议仍是后续设计，未实现。架构见[模块化单体](architecture.md)。

## 命名用例与协议边界

前端与 Buddy 共用业务 API：创建/修改任务、commit 时间线、认领/结束执行、提交/撤回结果、评审、取消/退回/重开、受权核对。HTTP 只处理认证入口、请求解析、限额及错误映射，调用经 Deps 注入的分领域命令模块；用例校验当前授权、依据与版本。内部固定修订、阶段写入、步骤内部准备动作不能独立暴露。

保留 cap/httpapi.Module 和 HTTP owner；路由按能力由 HTTP modules 列表配置组合，模块内部可按普通包组织，不固定九个模块；业务命令通过 flow 接口读取阶段与推导步骤，API 不重复判断流程。具体 URL/DTO 按 M04/M05 消费者定义，不预造一套完整接口。统一错误区分授权拒绝、版本冲突、业务等待、非法请求及技术失败，返回当前阶段、可用操作、阻塞原因与对象版本。

任务系统不派发远端 Agent、不组装上下文、不建另一套回调协议。Buddy 从通用 feed 得知变化、按需读业务 API，在已有 Agent 层执行 steer/唤醒/去重和防止自回复；通知不授予执行权。OpenExecution 成功后才能提交正式结果。

## 一致性与事件

同任务命令模块经 Deps 组合事实与 flow，在一个事务内写业务事实、必要阶段、审计及 outbox；成功响应反映已提交的本任务结果，待验收由事实推导，不依赖后台 Hook 建评审。两条异步消费路径独立：授权变化流给前端/Buddy；后台对父子/依赖目标核对并生成提醒。消息即使不改阶段也产生变化，收件箱不是可靠 feed 的来源。

Change 包含事件 ID、游标、任务 ID、对象引用/版本、操作 ID、变更类型和服务端时间；只有确有阶段变化才带前后阶段。TaskVersion、commit及需求版本不混用。前后版本在事务中捕获，不推送时用当前数据伪造历史。不发送完整上下文、凭据或未授权摘要。

## 快照、权限与恢复

客户端先取 StartCursor，再读授权快照，再从游标补拉/订阅；按对象版本去重/重读，不假定多个接口天然一致。游标受租户、主体和过滤范围约束，不能用 SQL 自增分配序冒充提交序。HTTP changes 与 WS 共用授权 feed，内部 outbox 不直接暴露。

动态订阅支持本人负责/参与或当前 Buddy 被分配的任务，服务端解释主体；新建/分配任务可被发现，不限初始 ID 列表。每次读取/投递重查当前权限；撤销停止投递，可发不泄露内容的访问失效提示。当前、历史、计数、搜索和附件统一范围约束。

Ack 仅是接收进度，各客户端 subscriptionID 独立；不能当作业务处理确认。重复投递可接受，保留期外明确 resync_required。慢客户端使用有界缓冲，溢出断开后补拉。M04 确定批量/保留/超时初值，M06 验证，不继承旧目标图未经验证的参数承诺。

## 认证与生命周期

HTTP 统一校验身份和浏览器 Origin；生产 Origin 显式允许，不默认任意来源。非浏览器请求不因缺少 Origin 免认证；凭据不放 URL，不允许订阅消息修改握手主体。连接期限/凭据撤销需明确策略。WS 只订阅/推送/确认，业务写入用 HTTP。

HTTP 拥有受管模块、连接和循环，根不重复登记；先资源就绪再接入，退出停接入并关闭连接/等待循环后释放存储。请求超时不能直接套用长连接。构造函数不监听或自启后台。

## 验证

M04—M06 覆盖同 API 的人/Buddy 权限差异、同事务结果可见、动态订阅、快照无漏窗、乱序去重、超期重同步、撤销、慢客户端和退出。真实 Buddy 的失效感知/升级需联调；测试客户端不是联调验收。

新增人工/异步确认按真实需求增加自己的记录、命名动作与 API；命令写入记录后调用 flow.Refresh，flow 推导时读取该记录。
