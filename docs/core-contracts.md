# 核心业务契约

本文是业务不变量的权威来源：所有流程步骤统一为 State，保留 FlowRef、同任务同步事务及 C01—C18 保护。机制见[架构](architecture.md)，流转见[状态模块与流程控制](task-flow-plugins.md)，权限见[成员与任务关系](permissions.md)。

## 身份、版本与证据

| 标识 | 权威语义 |
| --- | --- |
| TaskID / TaskVersion | 稳定任务身份及业务并发版本；消息/心跳不机械递增任务版本 |
| Basis | 目标、标准、正式输入及相关计划修订；普通聊天不是依据变更 |
| RoundID | 一轮工作及其绑定依据；正常推进不变，退回/重开采用新轮 |
| FlowRef | 定义 ID、版本及行为摘要，绑定配置组合及规则兼容边界 |
| ExecutionID / Writable | 执行记录及其写资格；失效后旧实例不能覆盖当前事实 |
| CommitID | 不可变正文与协作记录的稳定标识 |
| SubmissionID | 绑定任务、轮次、Basis、执行和精确结果 commit的交付 |
| ReviewID | 绑定 SubmissionID、结果 commit、BasisVersion 与验收人的结论 |

取消/更换 Buddy/实例不更换人的负责人。旧轮交付和验收保留历史，不自动继承到新轮。步骤在一轮内只前进、最多进入一次，步骤记录以 RoundID + 步骤键（加候选 SubmissionID）标识，Enter 据此幂等；正常推进不使同 RoundID 交付失效。

目标、标准、正式输入版本变更使当前轮需要重新评估，未应用新依据前不能提交当前有效结果或完成。优先级/期限等不强制新轮。活跃任务显式 Return，终态显式 Reopen；产品可将采用要求与该动作组合为一次受权命令，但仍须同事务失效旧执行写资格。首版不自动跨轮复用结果。

## 执行与写入隔离

处理人可以是人或 Agent。人工处理使用相同的轮次、依据、执行写资格和正式交付；服务端登记 Manual 执行，不要求 Agent 实例。当前人工处理人可在仍有参与权限时转交；转交隔离原执行写资格，负责人和验收人不变。下述写入隔离规则同样适用。

OpenExecution 校验当前阶段、依据、依赖、授权及 Buddy/实例归属，在同事务最多认领一项有效执行；未指定 Buddy 时先在事务外可信解析默认关系，事务内核对本地有效版本。客户端自述身份不可信。

执行没有租约或超时：服务端只记录执行者最近一次进展时间（认领、留言、提问、提交结果），供负责人判断是否介入（留言、转交、取消），不据此改变执行状态或自动重派；在线、心跳和沉默都不改变执行事实。更换实例创建新执行。没有单独的“结束执行”命令：提交结果不结束执行，执行在被失效或任务进入终态前保持可写。

执行只有“写入资格”（Writable）这一个生命周期事实：转交、同一处理人在新实例上重新认领、退回、重开和取消都会立即失效旧执行的写资格，之后它的提交、留言、提问都会被拒绝。Taskloom 观察不到外部进程，也不维护“已停止/安全退出”状态，不设停止证明、结束报告或负责人停止命令；任何关卡都不等待执行者停下。外部副作用由 Agent 层自行约束，旧执行者在下一次读写时得知自己已失效。任务完成只取决于有效结果、验收与未答问题。


Agent 接入方（MCP 或未来 Harness 插件）负责认证、认领后启动运行、定期汇报进展、处理新消息和输入、显式提交结果，并在写入被拒绝、执行失效时停止自己的外部工作。重连不自动新建执行，先读取当前执行及其写资格；事件可以重复，Ack 只代表收到，断线和在线均不证明运行状态。任务系统不负责 steer、上下文或工具清理，不承诺远端工具副作用被撤销或恰好一次。

## 交付与验收

明确 SubmitResult 才产生交付，普通聊天/进度/执行成功不产生。正文仅存在commit，交付保存稳定引用；附件固定版本，链接只固定 URL。文本首阶段明确拒绝未支持文件，不注入空成功材料能力。

任务绑定的步骤组合是验收要求唯一来源：包含人工验收步骤时由该步骤判定通过；无该步骤时不要求人工验收。manual/none 仅是派生展示值，不是另一份配置。Policy 只保存验收人/职责分离，默认创建时人的负责人，转交不暗改（首版验收人固定为负责人，职责分离尚未实现）；无相应步骤不得配置 reviewer。职责分离开启时核对实际执行者、代理归属及提交者，不能用自己的 Buddy 绕过。当前权限与资格持续校验，历史策略不冻结授权。

新提交、撤回、验收人/职责分离修改（后两者首版尚无入口），在同一命令事务由已到达的人工验收状态 Enter 幂等替换/清空当前评审，使旧组合 superseded；旧评审点击通过冲突。追加更正 commit 不改旧交付；新 commit 须重新提交。撤回不恢复更早结果。模式 none 仍要求有效结果、当前依据、依赖/必要子任务、无阻塞输入。

终态不接受改变当前交付/评审的普通命令，须显式重开；历史commit不会改写已完成证据。授权删除材料可使历史内容不可用，但不能伪造旧结论。

业务审核规则是提交后的状态步骤，不是登记前 checks：审核 wait/reject 保留合法交付并阻止推进；格式/授权/执行写资格/依据不合法拒绝提交，技术错误整体回滚。所有已到达步骤的结论须绑定当前证据，补交后不能只重验最后一个步骤。状态自己拥有审核记录，交付模块只存候选引用。

## 命令、权限与事务

通过配置装配的分领域命令模块是外部命令边界。runtime/command 统一事务、幂等和记录生命周期，不是服务定位器；授权及具体业务检查由用例显式调用。执行顺序：

1. 认证取得租户、实际主体和代理归属。必要远端身份读取在事务外完成，事务内校验本地有效版本；声明撤销同步有效期和失败策略。
2. 幂等命名空间为 tenant + actual subject + operation + key，强类型请求计算稳定摘要。同键不同内容冲突；重放前仍校验当前身份及返回结果读取权限，不再执行写入。
3. 同一 SQL 事务认领请求、校验预期版本和当前授权，按需原子消费精确确认；内部子操作沿用父 CommandID 和实际主体，不能二次消费或绕过范围。
4. 业务、版本、必要审计、outbox 和回执统一提交。领域间加入同一事务；内层失败即 rollback-only，即使捕获也不能部分提交。
5. 正式拒绝的安全审计在回滚后独立短事务追加；记录器不偷偷开事务。无远端调用置于持锁事务或可自动重试回调内。

当前所有写事务开头更新同一协调行，全库写入串行化（含只读命令事务），以此防止检查后被并发推翻；这是有意的简化，吞吐上限需在 M11 评估。改为按任务加锁前，各仓储须自带版本条件更新：任务依据与流程位置已是 CAS（位置写入要求预期版本并比对原值）。SQL 具体隔离、唯一约束、死锁重试在 M03 验证，不把自增分配序当提交序。S3 无共享事务，上传/删除使用显式状态和可重试补偿。

默认拒绝，企业、历史、搜索、事件、文件均校验当前范围。Buddy 不自动继承所属人权限；任务授权不等于外部工具授权。后台 automation 由可信内部入口产生，仅有租户/任务动作范围，保留 Cause 和原发起者，不替用户验收或自授工具权限。

首次管理员与恢复仅受控 bootstrap/离线运维路径，保留操作者与原因，无匿名初始化或普通 API 自授管理员。第一阶段不建设通用确认工作流；需要确认但尚未支持的 Buddy 动作拒绝或交由有权限的人直接执行，不默认放行。第二阶段确认绑定精确动作、对象、依据、主体及有效期。

## 契约验收案例

以下 ID 延续既有案例；各阶段实际验证情况见对应 M03—M05 实现说明。

| 编号 | 场景 | 必须成立 |
| --- | --- | --- |
| C01 | 执行阶段交付后进入验收 | RoundID 不变，结果 commit仍有效，不以进入状态标识废弃结果 |
| C02 | 验收退回 | 新轮回定义允许的较早状态（默认 ready），当前结果为空，旧结果/结论保留 |
| C03 | 完成后重开 | 新轮进入定义的 reopenState（默认 ready），旧通过记录不能直接再次完成 |
| C04 | 同轮失败重试/换 Buddy | 新执行记录，旧执行失效不能覆盖，负责人不变 |
| C05 | 创建时材料不足 | 同事务建立 ready 并展示等待，不依赖异步初始化 |
| C06 | 提交后执行仍可写 | 可建评审；验收通过即完成，不等待执行者停下，完成后旧执行写入被拒绝 |
| C07 | 断线后换实例 | 沉默不改变执行、不自动重派；新实例重新认领即失效旧执行，旧执行结果拒绝 |
| C08 | 取消后旧执行写入 | 取消同事务失效写资格；旧执行提交/留言/提问均被拒绝，不恢复任务 |
| C09 | 验收策略矛盾 | none 带 reviewer 或试图另设模式拒绝，是否需验收仅由绑定步骤组合决定，额外矛盾模式字段拒绝 |
| C10 | 新结果与旧评审并发 | 提交事务创建新评审，旧点击通过冲突 |
| C11 | 撤回后补交 | 当前评审清空，不回退旧结果；补交建立新评审 |
| C12 | none 模式有效结果 | 满足其他条件即可完成，无额外验收表单；文件/链接在第二阶段验证 |
| C13 | 创建回复后交付失败 | 回复/交付/评审/阶段/引用/回执全部回滚 |
| C14 | 一次确认创建多个子任务 | 第二阶段父命令一次消费、逐对象检查，失败整体回滚 |
| C15 | 已提交请求重放但权限撤销 | 当前身份/读取权限失败，不泄露旧结果，不新增写入 |
| C16 | 嵌套失败被捕获 | rollback-only 防止部分提交，拒绝审计可独立保存 |
| C17 | 身份服务慢 | 不持有业务锁等待远端，无有效依据明确失败 |
| C18 | 管理员初始化与离职恢复 | 仅受控运维入口，完整审计，无匿名提权 |

实现约定：版本冲突来自领域 CAS，共享错误在 cap/fault，事务包只管理加入/回滚；State 检查结果不将准备完成等同任务完成。
