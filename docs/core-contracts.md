# 核心业务契约

本文是业务不变量的权威来源。机制见[架构](architecture.md)，流转见[任务流程](task-flow.md)，接口与权限见 [API 与权限](api.md)。

## 标识与版本

| 标识 | 语义 |
| --- | --- |
| TaskID / BasisVersion | 稳定任务身份与唯一交付依据版本：随标题、目标、标准或必需子任务集合变化；认领、交付、验收、依据修改、子任务调整都固定它，留言、进展、移动项目、非必需子任务变化不改变它 |
| RoundID | 一轮工作；正常推进不变，只有重开已取消任务（Restart）新建 |
| Acceptance | 创建时固定的验收方式 manual/none：创建请求指定，未指定时人建任务取部署默认、Agent 建子任务为 none；此后固定，部署配置变更不影响已有任务 |
| ExecutionID / Writable | 一次执行及其写资格；Agent 执行绑定认领所用凭据 |
| CommitID | 不可变正文与协作记录，可带本任务文件与外部链接 |
| FileID | 一个不可变文件版本，属于一个任务；重新上传即新版本、新 ID |
| 交付登记 | 以结果 commit 为键，把轮次、执行和该 commit 登记为当前交付，不另设 ID；作者、时间和依据版本是该 commit 的事实，不另存 |

人是默认负责人；更换处理人、Agent 或实例都不更换负责人。负责人只能经显式移交更换（当前负责人或管理员，移交给有效人类成员，固定所见的原负责人）：管理与验收资格随之转移，处理人、执行与依据不变，原负责人保留为参与者；验收只认当前负责人的结论，移交前原负责人给出、尚未使任务完成的结论不再计入。旧轮交付与结论保留在历史中，不继承到新轮。

## 执行与写入隔离

- 处理人可以是人或 Agent。分配给人时同事务建立人工执行；Agent 须自己认领，校验所见依据版本、明确分配与授权，执行绑定本次请求的凭据。Taskloom 能核实的实例身份只有凭据，客户端自述的实例标识不可信也不记录。
- 执行只有一个生命周期事实：写资格。转交、换凭据重新认领、依据变更后重新认领、取消都同事务失效旧执行；之后它的提交、留言、提问都被拒绝（冲突）。留言与提问没有执行编号，旧执行按凭据识别：该凭据在本任务上有过执行、现在没有可写执行。人不是实例，人工执行失效不影响本人留言；从未执行本任务的 Agent 实例按参与者留言。
- 执行没有租约、心跳或超时，只记录执行者最近进展时间（认领、本人留言、提问、提交），供负责人判断是否介入；沉默不改变执行，也不自动重派。
- Taskloom 不维护"已停止"状态，任何关卡都不等待执行者停下；外部副作用由 Agent 层约束，旧执行者在下一次读写时得知失效。
- 依据在活跃任务上随时可改：旧依据上的执行不能再提交，旧依据上的结果不再有效，执行者按新依据重新认领。

Agent 接入方负责认证、认领后运行、汇报进展、处理新消息与问题、显式提交结果，并在写入被拒绝时停止外部工作；Taskloom 不负责 steer、上下文或工具清理。

## 交付与验收

- 只有明确的 SubmitResult 产生交付；普通评论、进度、执行成功都不算。正文只在 result commit 中，交付登记只存引用。同一执行、轮次、依据下重复提交相同正文、文件和链接返回原交付，任一项不同即替换当前结果。
- 是否需要验收只由任务的 Acceptance 决定；验收人固定为当前负责人（指定验收人、职责分离尚未实现）。
- 人验收目标，不必验收每一步：Agent 拆出的子任务默认 none，完成即解除父任务的提交限制；父任务按自己的 Acceptance 由负责人验收汇总结果，负责人随时可读子任务的时间线与结果。确需逐步验收时，建子任务时显式指定 manual。
- 验收结论就是一条 commit：类型 `review.approved` 或 `review.rejected`，正文为理由（退回必须有理由），引用被验收的结果 commit，并记下依据版本。当前结论是引用当前结果的最新一条；新提交后旧结论自然不再适用，对旧结果的通过冲突。待验收不存记录，由"有当前交付且无结论"推导。
- 没有撤回：执行者重新提交替换当前结果，负责人可带理由退回。更正追加新 commit 引用旧记录，不改旧交付或结论；要成为新结果必须再次提交。
- 任务完成只取决于：本轮有依据版本为当前的交付、manual 时负责人已通过、本轮没有未回答的问题、所有直接必需子任务已完成。完成不等待执行者停下。
- 终态拒绝改变当前结果的普通命令。只有 cancelled 可显式重开；活跃任务不开新轮，结果、人和需求分别经验收退回、转交和修改依据调整；completed 不可离开，返工须新建任务，因此完成事实不会被撤回。

## 文件与链接

- 文件先上传、后引用：字节先持久写入 blob 存储（本地目录或 S3），再在 SQL 登记为任务上的文件版本，登记行存在即字节已保存，不另设上传状态。二者无共享事务：上传失败、中断或幂等重放时删除这次新写的字节（S3 分段上传失败即中止）；删除失败或进程崩溃只留下不可达的字节，不留下可见记录，也不另建清理记录或组件。备份须同时覆盖数据库与 blob 存储。
- 评论（含更正）和结果可带文件与链接，正文、文件、链接至少一项；commit 只保存 FileID 与链接，不复制字节或元数据。引用的文件必须已登记在同一任务且对作者可见（已被引用，或作者自己的上传），否则整条命令回滚；他人尚未引用的上传不能被引用公开。文件版本不可变，引用它的 commit 存在多久它就保留多久；当前没有删除文件的能力（未引用的上传只有上传者可见），因此也不存在引用与删除的竞争。
- 链接只保存 URL（http/https）与标题，不承诺页面快照，目标内容变化不影响交付登记。
- 上传需要该任务评论资格，下载与列出需要该任务读资格，每次请求重新鉴权。未被任何 commit 引用的上传只有上传者可见，被引用后对任务读者可见（引用即分享，不可撤回）；其他情况与 FileID 跨任务一样按不存在处理。下载一律作为附件并以沙箱方式返回，上传的 HTML/SVG 不在本站执行；存储字节与登记大小不符时中断连接，不返回看似完整的响应。

## 任务拆分

- 父子关系只表达工作分解：一个任务最多一个父任务，同租户。子任务必须比父任务新（按任务创建时分配的全局序号，不用墙钟时间），父链上创建顺序严格递减，因此不会成环，无需遍历祖先；代价是不能把已有的更早任务挂到更新的父任务下，汇总时在新父任务下新建子任务。项目授予其负责人和成员（人或 Agent）对项目内每个任务等同参与者的资格（读、留言、提问、上传），不授予管理或验收；父子关系不授予访问，父子任务可分属不同项目，各自移动项目不受关系影响。只存当前关系，变化记录为父任务时间线上的 `plan.changed` commit。
- Required 表示父任务缺它不能交付。直接必需子任务全部 completed，父任务才能提交结果；cancelled 不满足，非必需不阻塞。父任务始终需要自己的结果与验收，子任务完成只解除提交限制，不自动提交或完成父任务。
- 必需子任务集合变化（挂接、切换 Required、重挂）使受影响父任务的依据版本递增，旧执行、结果、验收随之失效；非必需关系变化不改依据，无实际变化不递增。
- 拆分有两条途径：父任务负责人或管理员可新建、挂接、调整子任务；持有父任务当前可写执行的 Agent 实例（按凭据识别）只能在该任务下新建子任务（可标为必需），不能挂接或重挂已有任务，也不能新建顶层任务。新建子任务可指定空间内任一有效人类成员为负责人；不指定时，人为本人、Agent 为父任务负责人。创建者不是负责人时同事务成为子任务参与者。新建时可同事务分配处理人，等同创建后立即分配：人须有新任务的分配资格（负责人或管理员）；Agent 可分配的范围由部署配置决定：默认空间内任一有效成员（人或 Agent），可限制为只能分配给自己或不能分配，见[两层配置](configuration.md#业务配置边界)；配置只约束之后的创建，不改已有分配。分配语义与分配命令相同：人随分配开始执行，Agent 须用自己的凭据认领。依据不完整（缺目标或标准）时分配冲突，整条创建回滚。Agent 自己新增必需子任务时，依据照常递增、旧结果与验收照常失效，但它的执行同事务改按新依据而不失效（它就是这次变更的作者）；其他人调整计划时执行照常失效。
- 关系只挂接、切换 Required 或重挂，不解除：不再需要的子任务改为非必需或取消，关系历史保留。关系变更涉及的父任务必须 active；已完成父任务的计划冻结。父任务取消不隐式取消子任务。已完成任务不可重开，故当前依据上的父结果一旦成立，其必需子任务保持完成，不存在跨任务回退或级联重开。
- 关系不授予访问：任务 ID 不是秘密，可出现在父任务时间线的 `plan.changed` 中；标题、状态等内容只对可读者返回，读取详情时逐次鉴权。快照的父/子列表只含可读任务，不可读的必需子任务只提示其存在。

## 命令、权限与事务

- 外部写入只经命名命令；客户端不能用任意 kind 或正文触发业务动作，commit 类型由对应命令决定。
- 每个命令在同一 SQL 事务内认证、鉴权、检查客户端固定的对象/版本、写领域事实与 commit、写事件（本任务，以及视图随之变化的直接父任务）、审计与幂等回执；失败整体回滚。幂等重放前重新鉴权，权限撤销后不泄露旧结果。
- 默认拒绝；任务、历史、事件逐次校验当前成员与任务关系。Agent 不继承所属人权限；任务授权不等于外部工具授权。
- 首个管理员与恢复只走受控离线 CLI，无匿名初始化。不建设确认工作流：Agent 不能执行的动作直接拒绝。

## 契约验收案例

C14（批量确认）与 C17（远端身份服务）对应能力尚未建设，已移出，实现时再恢复。

| 编号 | 场景 | 必须成立 |
| --- | --- | --- |
| C01 | 交付后进入验收 | RoundID 不变，结果 commit 仍有效 |
| C02 | 验收退回 | 退回结论留在时间线；执行者补交新结果后重新待验收 |
| C03 | 完成后要求返工 | Restart 冲突，完成事实不变；返工新建任务。取消后重开时新轮从事实重新推导，旧轮交付和通过不能直接再次完成 |
| C04 | 同轮重试/换 Agent | 新执行记录，旧执行失效不能覆盖，负责人不变 |
| C05 | 创建时信息不足 | 同事务建立流程位置并显示等待原因 |
| C06 | 提交后执行仍可写 | 验收通过即完成，不等执行者停下；完成后旧执行写入被拒绝 |
| C07 | 断线后换实例 | 沉默不改变执行；新凭据重新认领即失效旧执行 |
| C08 | 取消后旧执行写入 | 取消同事务失效写资格；旧执行提交/留言/提问均被拒绝 |
| C09 | 验收方式变更 | 部署改为 none 不影响已有 manual 任务；none 任务拒绝验收结论；未知验收方式启动前拒绝；创建请求中的未知验收方式返回 400 |
| C10 | 新结果与旧结论并发 | 新结果使旧结论不适用，对旧结果的通过冲突 |
| C11 | 执行中修改依据 | 旧执行不能提交、旧结果不再有效；按新依据重新认领后可提交 |
| C12 | none 模式有效结果；文件/链接结果 | 满足其他条件即完成；结果可只有文件或链接；引用不存在或他任务的文件整条回滚；上传失败、中断、超限或重放不留下可见文件；撤销参与或成员后不能再读历史文件 |
| C13 | 交付后续写入失败 | 结果 commit、交付、阶段、事件、回执全部回滚 |
| C15 | 重放时权限已撤销 | 拒绝，不泄露旧结果，不新增写入 |
| C16 | 嵌套失败被捕获 | rollback-only 防止部分提交，拒绝审计独立保存 |
| C18 | 管理员初始化与恢复 | 仅受控运维入口，完整审计，无匿名提权 |
| C19 | 必需子任务未完成时父提交 | 冲突，不产生结果 commit 或交付；全部完成后可提交，父仍需自己的验收 |
| C20 | 调整必需子任务 | 父依据递增，旧执行/结果/验收失效；非必需调整与无变化不递增；重挂同时影响原父和新父 |
| C21 | 环、更早的子任务、终态父与过期所见 | 挂接冲突（成环必然把更早的任务挂到更新的任务下）；跨项目挂接与树内任务单独移动项目都允许 |
| C22 | 执行中的 Agent 拆分本任务 | 只有当前可写执行的实例可新建子任务；新增必需子任务后父依据递增，该执行不失效，必需子任务完成前父任务不能提交；未认领、已失效、另一实例、顶层任务与非人类负责人均拒绝；负责人调整计划仍使执行失效 |
| C23 | Agent 自主推进拆分 | Agent 建子任务未指定验收方式即为 none，指定 manual 则需负责人验收；可同事务分配处理人，默认可分配给任一有效成员，配置为 self 时分配他人、为 none 时任何分配都拒绝，越权或依据不完整时整条创建回滚；分配给 Agent 后须认领才有执行；父任务仍按自己的验收方式完成 |
