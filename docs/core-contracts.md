# 核心业务契约（M01）

更新：2026-11-18。M01 按所有流程步骤统一为状态插件修订，保留 FlowRef 与同任务同步事务；保留 C01—C18 的核心保护。本文是业务不变量的权威来源，机制见[架构](architecture.md)，流转见[状态模块与流程控制](task-flow-plugins.md)。尚未实现或业务验证。

## 身份、版本与证据

| 标识 | 权威语义 |
| --- | --- |
| TaskID / TaskVersion | 稳定任务身份及业务并发版本；消息/心跳不机械递增任务版本 |
| Basis | 目标、标准、正式输入及相关计划修订；普通聊天不是依据变更 |
| RoundID | 一轮工作及其绑定依据；正常推进不变，退回/重开采用新轮 |
| FlowRef | 定义 ID、版本及行为摘要，绑定配置组合及规则兼容边界 |
| PolicyRevision | 验收者与职责分离的不可变策略修订；验收要求唯一由 FlowRef 绑定的步骤组合决定 |
| ExecutionID / Generation | 执行记录和任务内单调隔离代次；旧实例不能覆盖当前事实 |
| MessageID + Revision | 正文的不可变修订 |
| SubmissionID | 绑定任务、轮次、Basis、执行/代次和精确回复修订的交付 |
| ReviewID | 绑定 SubmissionID、回复修订、CriteriaRevision、PolicyRevision 的结论 |

取消/更换 Buddy/实例不更换人的负责人。旧轮交付和验收保留历史，不自动继承到新轮。EntryID 标识一次状态进入以保证 Enter 幂等；正常推进改变 EntryID 不使同 RoundID 交付失效。

目标、标准、正式输入版本变更使当前轮需要重新评估，未应用新依据前不能提交当前有效结果或完成。优先级/期限等不强制新轮。活跃任务显式 Return，终态显式 Reopen；产品可将采用要求与该动作组合为一次受权命令，但不能绕过停止保护。首版不自动跨轮复用结果。

## 执行与停止

OpenExecution 校验当前阶段、依据、依赖、授权及 Buddy/实例归属，在同事务最多认领一项有效执行；未指定 Buddy 时先在事务外可信解析默认关系，事务内核对本地有效版本。客户端自述身份不可信。

RenewExecution 是执行保活，不由 WS ping 替代；超时仅标记 unknown 并保留归属，不自动重派。相同实例未失效代次可续用；更换实例创建新执行。结束执行与提交结果独立：结束且未失效/取代的执行可补交遗漏结果；提交后可继续收尾。

正常 EndExecution、匹配旧代次的停止确认、受权管理员记录的外部停止/隔离证明可解除安全等待。租约过期、断线、数据库代次失效均不证明外部工具已停。Return/Reopen/替换执行及完成必须核对安全退出；Cancel 立即记录终止业务意图及代次失效，停止待确认事实继续保留。

停止回执严格关联旧 ExecutionID/Generation，即使取消使业务写代次失效，仍可关闭对应旧停止待办；不能改新执行或恢复任务。恢复入口展示业务状态、写入权、外部停止三种事实；管理证明记录操作者、证据范围与原因。真实 Agent 能提供的停止保证在 M06 联调核验。

## 交付与验收

明确 SubmitReply 才产生交付，普通聊天/进度/执行成功不产生。正文仅存在消息修订，交付保存稳定引用；附件固定版本，链接只固定 URL。文本首阶段明确拒绝未支持文件，不注入空成功材料能力。

任务绑定的步骤组合是验收要求唯一来源：包含人工验收步骤时由该步骤判定通过；无该步骤时不要求人工验收。manual/none 仅是派生展示值，不是另一份配置。Policy 只保存验收人/职责分离，默认创建时人的负责人，转交不暗改；无相应步骤不得配置 reviewer。职责分离开启时核对实际执行者、代理归属及提交者，不能用自己的 Buddy 绕过。当前权限与资格持续校验，历史策略不冻结授权。

新提交、撤回、验收人/职责分离修改，在同一命令事务由已到达的人工验收状态 Enter 幂等替换/清空当前评审，使旧组合 superseded；旧评审点击通过冲突。正文编辑不改旧交付；新修订须重新提交。撤回不恢复更早结果。模式 none 仍要求有效结果、当前依据、依赖/必要子任务、无阻塞输入及安全退出。

终态不接受改变当前交付/评审的普通命令，须显式重开；历史消息修订不会改写已完成证据。授权删除材料可使历史内容不可用，但不能伪造旧结论。

业务审核规则是提交后的状态步骤，不是登记前 checks：审核 wait/reject 保留合法交付并阻止推进；格式/授权/代次/依据不合法拒绝提交，技术错误整体回滚。所有已到达步骤的结论须绑定当前证据，补交后不能只重验最后一个步骤。状态自己拥有审核记录，交付模块只存候选引用。

## 命令、权限与事务

通过配置装配的分领域命令模块是外部命令边界。runtime/command 统一事务、幂等和记录生命周期，不是服务定位器；授权及具体业务检查由用例显式调用。执行顺序：

1. 认证取得租户、实际主体和代理归属。必要远端身份读取在事务外完成，事务内校验本地有效版本；声明撤销同步有效期和失败策略。
2. 幂等命名空间为 tenant + actual subject + operation + key，强类型请求计算稳定摘要。同键不同内容冲突；重放前仍校验当前身份及返回结果读取权限，不再执行写入。
3. 同一 SQL 事务认领请求、校验预期版本和当前授权，按需原子消费精确确认；内部子操作沿用父 CommandID 和实际主体，不能二次消费或绕过范围。
4. 业务、版本、必要审计、outbox 和回执统一提交。领域间加入同一事务；内层失败即 rollback-only，即使捕获也不能部分提交。
5. 正式拒绝的安全审计在回滚后独立短事务追加；记录器不偷偷开事务。无远端调用置于持锁事务或可自动重试回调内。

同任务关键事实变更以任务协调锁和证据版本防止检查后被并发推翻；跨节点命令锁顺序固定。SQL 具体隔离、唯一约束、死锁重试在 M03 验证，不把自增分配序当提交序。S3 无共享事务，上传/删除使用显式状态和可重试补偿。

默认拒绝，企业、历史、搜索、事件、文件均校验当前范围。Buddy 不自动继承所属人权限；任务授权不等于外部工具授权。后台 automation 由可信内部入口产生，仅有租户/任务动作范围，保留 Cause 和原发起者，不替用户验收或自授工具权限。

首次管理员与恢复仅受控 bootstrap/离线运维路径，保留操作者与原因，无匿名初始化或普通 API 自授管理员。第一阶段不建设通用确认工作流；需要确认但尚未支持的 Buddy 动作拒绝或交由有权限的人直接执行，不默认放行。第二阶段确认绑定精确动作、对象、依据、主体及有效期。

## 契约验收案例

以下 ID 延续既有案例；描述更新为 M01 机制，不表示已经测试通过。

| 编号 | 场景 | 必须成立 |
| --- | --- | --- |
| C01 | 执行阶段交付后进入验收 | RoundID 不变，回复修订仍有效，不以进入状态标识废弃结果 |
| C02 | 验收退回 | 安全退出后新轮回定义允许的较早状态（默认 ready），当前结果为空，旧结果/结论保留 |
| C03 | 完成后重开 | 新轮进入定义的 reopenState（默认 ready），旧通过记录不能直接再次完成 |
| C04 | 同轮失败重试/换 Buddy | 新执行与代次，旧实例不能覆盖，负责人不变 |
| C05 | 创建时材料不足 | 同事务建立 ready 并展示等待，不依赖异步初始化 |
| C06 | 提交时执行仍收尾 | 可建评审；通过后仍等待退出，结束命令同步核对完成 |
| C07 | 断线后换实例 | 无停止/隔离证据拒绝重派，旧代次结果拒绝 |
| C08 | 取消后旧停止回执 | 仅更新匹配旧执行的待确认项，不恢复任务或改新执行 |
| C09 | 验收策略矛盾 | none 带 reviewer 或试图另设模式拒绝，是否需验收仅由绑定步骤组合决定，额外矛盾模式字段拒绝 |
| C10 | 新结果与旧评审并发 | 提交事务创建新评审，旧点击通过冲突 |
| C11 | 撤回后补交 | 当前评审清空，不回退旧结果；补交建立新评审 |
| C12 | none 模式有效结果且安全结束 | 满足其他条件即可完成，无额外验收表单；文件/链接在第二阶段验证 |
| C13 | 创建回复后交付失败 | 回复/交付/评审/阶段/引用/回执全部回滚 |
| C14 | 一次确认创建多个子任务 | 第二阶段父命令一次消费、逐对象检查，失败整体回滚 |
| C15 | 已提交请求重放但权限撤销 | 当前身份/读取权限失败，不泄露旧结果，不新增写入 |
| C16 | 嵌套失败被捕获 | rollback-only 防止部分提交，拒绝审计可独立保存 |
| C17 | 身份服务慢 | 不持有业务锁等待远端，无有效依据明确失败 |
| C18 | 管理员初始化与离职恢复 | 仅受控运维入口，完整审计，无匿名提权 |
