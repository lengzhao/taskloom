# 必需子任务最小设计

日期：2026-11-20。

状态：设计方案，尚未实现。用户已确认两项决策：

- 必需子任务完成后才能提交父结果；
- 已完成的任务一律不能重开，需要返工时新建任务。

本次只整理设计，不开始实现。当前实现仍以 [核心契约](../core-contracts.md)、[任务流程](../task-flow.md)及 `cap/*` 为准。

## 目标与边界

支持负责人将工作拆给不同人或 Agent，等必需子任务完成后汇总交付。以 [NEX-1251](https://nexv2.ambr.io/cards/NEX-1251) 的资料准备、开发实现和父任务汇总为具体场景；不复制其全部机制。

第一性原理：父子关系表达工作分解；必需约束表达父交付缺少哪项工作；子任务完成只证明子任务自身的交付与验收，不证明父目标达成。

本期只做单父树和必需子任务完成约束。不做通用依赖图、兄弟任务前置关系、自动派发、自动汇总、自动重开、成组规划、任意整树操作、历史树恢复或新的审批引擎。不因本设计增加阶段或流程插件。

## 已完成即终态

completed 成为不可离开的终态，对所有任务生效，不只针对子任务：

- Restart 拒绝 completed；活跃任务的退回和 cancelled 任务的重开保持不变；
- Cancel、Edit 本来只作用于 active，不改变 completed；
- 需要返工时新建任务，可在正文引用旧任务；首版不建“来源任务”字段。

理由：完成表达当时交付和验收成立的事实。允许重开会让“已完成”可撤回，任何依赖它的判断都要处理回退：父依据跨任务失效、子回退与父验收并发、祖先是否连带重开。禁止重开后，这些机制整体删除，而不是换成更轻的变体。

这项规则独立于子任务，已于 2026-11-20 先行落地（flow.Restart、相关测试、界面与核心契约等文档），见“契约与代码影响”。

## 事实模型

每个节点复用现有 Task、commit、执行、交付、验收和流程位置，有独立负责人和处理人。

只新增当前父子关系事实：

| 字段 | 约束与用途 |
| --- | --- |
| Tenant | 与两端任务一致，沿用租户隔离 |
| ChildID | 同租户唯一，一个任务最多一个父任务 |
| ParentID | 工作分解所属任务，不能等于 ChildID |
| Required | 是否阻止父任务交付；创建关系默认 true，命令可以明确设为 false |

无关系即独立根任务。保留 Required 是因为“属于这项工作”和“缺它不能交付”不同；无需另设依赖表表达同一事实。

不保存根 ID、深度、子任务计数、完成比例、阻塞状态、依赖满足标志或父任务进度。当前关系是权威查询来源，不靠重放历史构建当前树。接口字段和存储布局在实施计划中确定，不预建无消费者字段。

关系变更在父任务上追加不可变 commit，记录前后值、原因及实际操作者，复用命令审计和事件。改变父依据的关系 commit 带递增后的 BasisVersion，使任一依据版本对应的必需子计划可从父任务历史读出（A07）。

## 核心不变量

已完成任务不再改变，因此必需子任务的“已完成”只能经父计划变化（增删、切换 Required、重挂）被改变，而这些变化都会使父 BasisVersion 递增。由此得到：

```text
父任务当前依据上存在有效结果
  ⇒ 提交该结果时所有直接必需子任务均 completed
  ⇒ 此后它们仍为 completed
```

完成判断因此不依赖异步传播，也没有任何子任务命令会改写父任务事实。

## 提交、验收和完成

直接必需子任务全部处于 completed，才满足子任务约束。cancelled 不满足；非必需子任务不阻塞。每个子任务自身已受相同规则约束，判断父任务时只检查直接子任务的权威阶段，不递归执行 Refresh。

父完成条件为：

```text
本轮有当前依据上的有效父结果
且 manual 时负责人已通过该结果
且本轮没有未回答问题
且所有直接必需子任务均 completed
```

检查点：

1. Submit：必需子任务未完成即冲突，不创建父结果 commit 或交付登记。判断由 flow 提供，与现有 CheckOpen 同类；结果命令只调用 flow，不另读关系。
2. flow 推导：子任务约束是 derive 的一项事实输入，同时决定等待项与 Refresh 是否完成，不另写一段完成检查。
3. Review 不新增检查：现有“结果依据须为当前 BasisVersion”的校验加上述不变量已足够。

普通留言、进展、提问、认领和分配仍按现有规则进行，不因子任务未完成停止父任务准备工作。none 模式同样必须先满足子任务约束再提交。

最后一个必需子任务完成，只解除提交限制，不自动提交、验收或完成父任务。处理人应检查子结果并明确提交汇总结果；系统只能核实提交和验收，不能保证正文实际使用了所有子结果。

## 查询与步骤推导

沿用 ready / executing / accepting / completed，不增加 blocked 状态。依据不完整仍为 ready；没有当前依据上的父结果仍为 executing。未完成必需子任务是推导出的等待项及 Submit 不可用原因。

任务快照按需提供父任务、直接子任务、是否必需及未满足的必需项。步骤、可用操作和等待项从同一组事实计算；现有单一 Waiting 文本可选择优先原因，但不能因此隐藏其他提交限制。

子任务等待不等于父处理人无事可做，不把子任务处理人直接变成父任务的 NextActor。父任务仍由自己的处理人负责汇总；子任务各自使用现有收件箱。权限过滤后才输出子任务信息，统计口径为可见子任务，不把数量比例称为目标完成度。

## 正式计划与依据有效性

现有 BasisVersion 只随标题、目标、标准变化。本设计将其扩大为“本任务交付依据的唯一版本”，必需子计划变化也使其递增，不增加 PlanVersion。

| 变化 | 父任务依据影响 |
| --- | --- |
| 增加、移除必需子任务 | 父 BasisVersion 递增 |
| Required 在 true/false 之间改变 | 父 BasisVersion 递增 |
| 必需子任务重挂到另一父任务 | 原父、新父分别递增，去重 |
| 增加、移除或重挂非必需子任务 | 记录关系变化，不改变交付依据 |
| 子任务从非完成变为完成 | 不递增；只解除父提交限制 |

依据递增后沿用现有版本比对：旧依据上的执行不能再提交，旧结果和旧验收不再有效，处理人按新依据重新认领；父任务 RoundID 不变。不为此额外撤销执行写资格，与现有 Edit 行为一致。无实际变化的关系命令不递增版本。

这里只影响直接相关的活跃父任务，不自动修改父目标、子目标或整棵树的依据，也不传播假想的自然语言影响。

## 返工、取消与终态

- 子任务返工：父任务仍 active 时，父负责人在父计划中新增必需子任务（父依据随之递增）。旧的已完成子任务可保留为必需（不阻塞），也可改为非必需或解除关系。
- 父任务返工：父已完成即不可重开，也不能调整其计划；新建任务（可作为新的根任务或挂到某个活跃任务下），在正文引用旧任务。
- 任一关系变更涉及的父任务必须 active，包括非必需关系变化和重挂的原父。由此，已完成父任务的整棵子树关系冻结；cancelled 父任务须先 Restart 才能调整计划。
- 父取消不取消子任务；子取消不满足父完成约束，仍需重开并完成该子任务、新增替代子任务或显式解除必需约束。
- 活跃必需子任务的退回、cancelled 必需子任务的重开照常允许：它们本就不满足父约束，不会使父倒退。
- 父任务完成后，非必需子任务可以继续工作。

不存在跨任务的重开或回退传播，祖先链上的完成事实不会被下层变化打破。

## 最小命令与授权

需要的命名能力是创建子任务、挂接已有根任务、切换 Required、解除关系、原子重挂。创建子任务应复用现有创建规则，关系命令不隐含分配或授权；没有可执行权限的 Agent 只能提出建议。

- 创建或管理父计划：父任务负责人或有效人类管理员；不新增可配置规划角色。
- 挂接已有任务、解除或重挂：还需拥有子任务管理资格；重挂检查原父、新父和子任务。
- 改 Required：检查父任务管理资格。父计划规则不授予修改子目标或执行内容的权限。
- 子任务自身命令不改写父任务事实，因而不存在借子任务权限改变父依据的路径。
- 读取任何节点、历史、结果和事件均独立鉴权，父子关系不授予访问权。

对无权读取的必需子任务，只向父任务有权读者提示“存在不可见的必需子任务”，不返回任务 ID、标题、处理人、结果、精确数量或阶段。业务校验仍检查全部真实关系。

关系命令固定所有被修改的父任务所见 BasisVersion、所见原关系和变更理由；事务中比较当前事实，冲突即拒绝。涉及终态子任务的组织关系调整不改其交付，但必须具备子任务管理资格；需要不同的目标须另建任务。

首版两端须同租户、同 ProjectID；有项目时须为同一未归档项目，无项目时可将独立任务挂入无项目树。拒绝跨项目挂接。已有树中节点不能单独移动项目，现有 SetProject 须增加该检查；需先按权限解除关系。整树项目迁移后置。

## 事务、并发与事件

沿用当前命令事务及全局写入串行化，在同一事务内检查关系唯一性、两端范围、祖先链无环、授权、预期依据和阶段，再写关系、必要的父依据递增、commit、事件、审计和幂等回执。任何失败整体回滚。

重挂不能拆成对外可见的先解除、后挂接。并发 A 挂 B 与 B 挂 A 最多一个成功。关系和项目修改也必须在同一写入边界校验，不能仅靠界面阻止。

子任务完成与父 Submit 并发：Submit 若先看到未完成事实则冲突，子完成先提交则 Submit 可通过。已完成任务不可重开，故不存在子回退与父验收的竞争。提交顺序决定事实，无异步放行窗口。

会改变父查询结果的子阶段变化（完成、取消、退回、取消后重开），应在原命令事务内为直接父任务写 task.changed 事件。各命令现由共用的 `finish` 收尾，统一在此处理：flow 在阶段变化时提供直接父任务引用，`finish` 写父事件；不给各命令模块分别注入关系读取。关系变化由关系命令通知前后影响任务的并集并去重。事件只包含重新读取所需的引用，读取时重新鉴权。

首版复用现有持久变化补拉，不新增跨任务自动推进 worker、周期扫描器或通知渠道。Agent 接入方看到父变化后自行读取、判断是否汇总；断线恢复仍用现有游标。以后新增通知时也不能承担提交和完成的安全校验。

### 必需子任务

新增一项内聚的父子关系能力，区分只读关系查询与关系命令所需写入；由 SQL 实现。

| 消费者 | 变化 | Deps |
| --- | --- | --- |
| flow | 读取直接关系与子任务阶段；推导等待项与完成；提供提交前检查；阶段变化时给出父任务引用 | 5 → 6，见下 |
| 关系命令（新） | 关系校验、父依据递增、commit、事件 | 实施时按真实字段计数并审查 |
| 结果命令 | Submit 调用 flow 的提交检查；Review 不变 | 不变（7） |
| 流程控制命令 | 不变 | 不变（5） |
| `finish` 及调用它的命令 | 写直接父任务事件 | 不变 |
| 工作区 SetProject | 拒绝已在树中的任务单独移动项目 | +1 关系读取；模块依赖已多，实施时审查是否改由关系能力提供检查 |
| task.Store | 新增“仅递增依据版本”的写方法，现有 UpdateBasis 须带正文 | 公共契约变更 |
| 查询、收件箱、HTTP/MCP、工作台 | 展示父/子、必需项与不可见提示 | 随实现确定 |

flow 的 Deps 从 5 变为 6，保留理由：这是已有完成推导增加的一项真实事实输入，拆为状态插件只会转移同一条件；提交检查复用同一输入，避免结果命令另读关系。跨模块只通过 typed Deps，不引入服务定位器、通用依赖执行器或流程条件注册机制。

前后端与 Agent 共用业务命令；阻塞原因是稳定代码，具体 DTO 和路径随实现一起确定。

兼容性：现有无关系任务除“已完成不可重开”外行为不变；新增关系为空不需要猜测旧数据。BasisVersion 语义扩大，客户端继续将其作为不透明依据版本处理；假定它只随正文改变的消费者必须更新。此文不修改当前核心契约或默认装配，实施时再同步代码、配置、API、任务流程和核心契约。

## 与现有规划的关系

[M08](../../todo.md) 原规划同时包含任务树、通用依赖、成组变更和异步核对。本设计仅覆盖其可独立交付的最小子集：树、必需约束、父独立结果、同步一致性和查询变化传播。兄弟任务执行前置条件仍不能表达，不用 Required 冒充通用依赖。

“已完成不可重开”收紧了 M05 已实现的重开范围，落地时同步清单中的 M05 描述。该设计不表示 M08 已完成，也不提前完成 M06 真实 Agent 联调。目标草案中的完整树历史、成组规划、通用依赖和跨树协作继续后置。

## 实现时必须验证的案例

1. 任一 completed 任务 Restart 被拒绝；活跃退回、cancelled 重开保持现有行为。
2. 必需子任务 active/cancelled 时，父 Submit 不产生任何交付；全部 completed 后可提交，manual/none 均成立。
3. 非必需子任务未完成不阻塞；父始终需要自己的结果，子完成不自动完成父。
4. 增删必需关系、切换 Required、重挂使正确父依据递增；旧执行、结果、验收不得复用；关系 commit 带新版本；非必需关系变化不改变依据；追加返工子任务使父依据递增。
5. 三层树仅在直接关系上判断；已完成父任务的关系变更（含重挂出其子任务）被拒绝；cancelled 父须先重开才能调整计划。
6. 并发挂接不能产生多父、自环或祖先环；范围、归档、项目移动检查不可绕过。
7. 关系引用不扩权，不可见子任务不泄露内容；子任务命令不改写父事实。
8. 事务中任一步失败全部回滚；子阶段变化写父事件，关系事件覆盖前后影响并集；重复命令不重复加版本，撤销权限后幂等重放仍被拒绝。
9. 无关系旧任务保持现有语义；匹配范围的测试通过后运行仓库 all/race 检查，并分别报告真实、模拟及未验证项。
