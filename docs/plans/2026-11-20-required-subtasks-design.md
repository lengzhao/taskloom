# 必需子任务设计理由

日期：2026-11-20。状态：首版已实现。

本文只记录设计取舍的理由。当前规则以[核心契约·任务拆分](../core-contracts.md#任务拆分)为准，推导与命令前提见[任务流程](../task-flow.md)，接口与权限见 [API](../api.md)，代码基线为 `cap/plan`、`cap/flow`。

## 目标与边界

支持负责人把工作拆给不同人或 Agent，等必需子任务完成后汇总交付；以 [NEX-1251](https://nexv2.ambr.io/cards/NEX-1251) 的资料准备、开发实现、父任务汇总为场景。

父子关系表达工作分解；Required 表达父交付缺少哪项工作；子任务完成只证明子任务自身的交付与验收，不证明父目标达成，所以父任务始终需要自己的结果。

不做：通用依赖图、兄弟前置关系、自动派发、自动汇总、自动重开、成组规划、整树操作、历史树恢复、新的审批引擎或阶段。这些不在 M08 范围内。

## 取舍

**已完成即终态。** 允许重开会让“已完成”可撤回，依赖它的判断都要处理回退：父依据跨任务失效、子回退与父验收并发、祖先是否连带重开。禁止重开后这些机制整体删除，而不是换成更轻的变体；返工新建任务。该规则对所有任务生效，先于子任务落地。

**只存当前关系。** 关系只有 ParentID、ChildID、Required；不存根、深度、计数、完成比例或阻塞标志，这些都可从当前事实推导。历史写在父任务时间线的 `plan.changed` commit。Required 单独保留，因为“属于这项工作”与“缺它不能交付”是不同事实。

**依据版本扩大，而非新增计划版本。** 必需子任务集合是父交付依据的一部分，因此它变化时递增父 BasisVersion，复用现有的旧执行/结果/验收失效逻辑。由此得到核心不变量：已完成任务不再改变，而改变必需集合必递增父依据，所以父任务在当前依据上的有效结果一旦成立，其必需子任务就保持完成。完成判断不依赖异步传播，子任务命令也不改写父任务事实。

**等待子任务不是步骤。** 步骤保持 ready/executing/accepting/completed；`WaitingOnSubtasks` 是推导出的等待原因，只拦提交，认领、讨论和准备照常。此时父任务没有固定的下一位行动者（未答问题除外），收件箱把它列为调用者自己的阻塞任务，而不是让子任务处理人成为父任务的 NextActor。

**放置只固定自己的对象。** 命令只比对调用者所见的原关系，不固定父任务依据版本，也不带理由：父任务改标题或新增别的子任务不应让放置冲突；操作者与时间已有审计和时间线。

**不解除关系。** 不再需要的子任务改为非必需或取消即可解除对父任务的限制，关系保留使历史完整；少一个写入路径，也少一套“需要子任务权限”的界面判断。

**不要求同项目。** 项目只是组织方式、不授予访问，强制同项目只会增加 SetProject 的跨模块检查。

**任务 ID 不是秘密。** 关系不授予访问；ID 可出现在时间线，详情读取逐次鉴权。快照列表只给可读子任务的内容，不可读的必需子任务只给存在提示。

**创建即放置。** 带 ParentID 的创建在同一事务内建任务并放置；放置规则只在 plan 模块，以 Placer 供创建调用，不嵌套命令。

**事件。** 子任务阶段变化由各命令共用的 `finish` 为直接父任务写 `task.changed`；放置命令通知子任务及前后父任务。不新增 worker、扫描器或通知渠道。

## 已知限制

- 工作区命令（如修改子任务标题）只通知本任务，父任务列表里的子任务标题要等父任务下次变化才刷新。
- 祖先链超过 64 层视为冲突，只用于防止损坏数据导致死循环。（2026-11-21 起改为"子任务须比父任务新"，不再遍历祖先，见[任务拆分](../core-contracts.md#任务拆分)。）
- 测试未覆盖：none 模式下的子任务约束、三层树、并发挂接（依赖全局写锁）、放置中途失败回滚的专项用例。
