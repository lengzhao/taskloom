# 默认交付：明确提交的结果回复

更新：2026-11-18，M01。尚无业务实现。身份/事务/验收以[核心契约](core-contracts.md)为准，生命周期见[可配置状态模块](task-flow-plugins.md)。

## 内容与所有权

默认交付是一条被明确登记的回复。会话模块拥有正文及不可变修订；交付模块拥有 Submission，人工验收状态拥有自己的 Review；材料模块在第二阶段拥有文件版本及保留引用；flow 模块独占阶段。普通聊天、进度、最后一条消息和模型 turn 结束均不是交付。

Submission 保存 TaskID、RoundID、Basis、ExecutionID/Generation、MessageID/Revision、提交者、时间和撤回事实，不复制正文。Review 绑定精确交付/回复/标准/策略修订。消息作者与提交者分别保留，不接受伪造作者。

## SubmitReply 用例

请求含任务/轮次/依据/执行代次、预期版本、幂等键及二选一内容：New 回复或 Existing 精确回复引用。常规 New 一次创建并登记；Existing 必须是同任务且作者/执行依据匹配的回复，不能直接登记他人消息。具体 DTO 随 M05 消费者定义。

结果命令模块通过 Deps 组合本地模块，步骤均处于同一事务：

1. 可信身份、当前权限、幂等、任务协调锁及版本检查；执行/依据有效，阶段允许提交。
2. 创建或读取精确回复修订；检查内容及附件授权，固定需要保留的版本。
3. 登记交付及当前引用；相同任务/轮次/代次/依据/回复修订的重复提交由领域唯一约束去重，不能仅依赖客户端重用幂等键。
4. 调用流程控制接口，已到达步骤通过幂等 Enter 同步当前证据，人工验收状态负责旧评审失效/新建；控制器按步骤结果推进。执行仍收尾时等待退出，不虚报完成。
5. 写审计、业务事件及幂等回执，统一提交。技术错误整体回滚回复、交付、引用、评审及阶段；业务审核 wait/reject 则提交合法结果并保留阻塞；Existing 失败不删除已有消息。

远端上传/链接访问不在事务里。普通 PostMessage 不登记结果，内部固定修订/引用接口不单独暴露。消息及交付事件共享操作 ID，客户端按稳定引用组织时间线。

## 编辑、撤回与结论

编辑创建新修订，旧交付仍引用旧修订；要成为当前结果须重新提交。Withdraw 清空当前轮结果，流程核对使已到达审核步骤的当前结论失效，保留历史，不自动恢复旧结果。accepting 无结果时保持等待，补交同事务由已到达的人工验收步骤建立新评审。标准变化需新轮，验收人变化新 PolicyRevision 并重建评审；旧点击通过冲突。

已完成/取消任务不接受普通提交或撤回改变当前证据，须显式重开。ended 且仍有效、未被取代的执行可在非终态补交遗漏结果。旧执行即使保留历史也不能覆盖当前候选。

## 分期与扩展

第一阶段只支持非空文本；文件/链接能力在 M07 接入前明确拒绝，不装配假成功材料能力。第二阶段允许非空文本、可用文件版本、合法链接任一种单独交付，不额外要求完成表单。

文件引用保留与删除并发受 SQL 约束，S3 操作使用补偿；企业合规删除可使内容不可用，历史如实标记。引用不扩大权限。链接固定 URL 和说明，不等于外部页面快照。

特殊产物质量/事实审核用独立状态插入执行之后，移除 Deps.checks 和独立校验引擎。审核未过保留合法交付并阻止完成，技术错误整体回滚；基础授权、执行隔离、内容合法性和依据有效性仍在提交前验证。远端检测通过步骤待办/outbox及正式结果事实，不在 Enter 中调用。无需第二套正文或产物表单。

验收覆盖 C01/C06/C10—C13、不同幂等键重复登记、旧评审并发、消息修订不漂移及第二阶段文件删除竞争；这些均未实现验证。
