# Collaboration P0 Implementation Plan

**Goal:** Agent 使用普通协作方法即可分工、完整读取成果、准确引用并提交人工验收。

**Architecture:** Taskloom 复用不可变结果 commit、现有查询鉴权和流程推导；AgentKit 复用当前会话已有的工具输出存储。只补读取与回执，不建设编排引擎或新持久化机制。

**Tech Stack:** Go、PluginKit、SQLite、HTTP/MCP、AgentKit。

**Spec:** 本轮用户确认的四项 P0：直接结果引用、按需分页正文、长工具输出续读、准确提交回执。

## Constraints and review focus

- 保持依据版本、执行写资格、租户及任务访问边界。
- 分页固定结果引用，不能把翻页期间的新结果拼入旧正文。
- Unicode 正文完整；非法游标与跨任务读取明确失败。
- 工具续读只访问当前会话的工具输出，不能读取任意路径。
- 人工验收仅由负责人真实决定；测试结果与部署状态分别报告。

## Tasks

- [x] Taskloom：为结果引用、完整分页、鉴权与提交状态写回归测试，验证失败后实现最小共享查询及 HTTP/MCP 适配。
- [x] AgentKit：为当前会话长输出续读、越权与 Unicode 写回归测试，实现现有输出存储上的通用工具并接入 preset。
- [x] 根据最终工具契约精简协作 skill，删除时间线考古、缓存路径与内部编号指导。
- [x] 运行两仓库规定检查；构建本地镜像，保留现有数据与配置。
- [x] 使用三个独立 Agent 主体，以普通业务目标验证并行分工、完整成果读取、引用汇总、提交与人工验收；结论见[开发说明](../../development.md#验证范围与已知限制)，过程证据未入库。

本计划覆盖实现与验证；提交、推送和 PR 按用户后续明确指令分别执行。
