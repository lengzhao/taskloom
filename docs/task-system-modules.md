# 任务系统模块划分

更新：2026-11-18，M01。模块定义接口和 Deps 后即成为可配置组合的插件，内部辅助函数不单独装配；边界和事务关系以[架构](architecture.md)为准，功能阶段以[覆盖表](requirements-coverage.md)为准。

| 模块 | 核心职责 | 第一阶段 |
| --- | --- | --- |
| task | 目标/标准/负责人/依据/策略修订 | 独立任务和必要历史 |
| collaboration | 独立 commit 时间线、commit、阻塞问题 | 文本和问答，回答不授予权限 |
| execution | 分配、认领、代次、保活、结束和停止证明 | 单有效执行、未知不重派 |
| delivery | 当前轮交付引用、撤回 | 文本结果，不管理评审 |
| state/accepting | 人工验收记录、结论与职责分离 | 可按流程配置省略 |
| state/fact-review | 自定义事实审核 | 扩展示例，不默认启用 |
| flow / state | 阶段、工作轮次、状态列表、幂等进入动作与证据重查 | 默认流程组合，同任务同步推进 |
| access | 主体、范围、动作授权 | 默认拒绝、租户隔离、管理员恢复 |
| plan | 单父树、依赖、成组变更 | 第二阶段 |
| artifacts | 文件版本、引用与补偿 | 第二阶段 |
| inbox/query | 提醒、搜索、聚合工作台 | 第一阶段最小查询，第二阶段扩展 |
| history | 历史树快照、差异与恢复 | 必要证据从首阶段保存，完整恢复第三阶段 |

分领域命令模块通过 Deps 协调上述规则，命令机制承担原子提交；不由万能 core/work Service 收集全部业务接口。HTTP 和后台调用同一命名用例，内部模块无全局服务查找。接口按真实消费者定义，SQL 仓储不决定领域规则。

父完成须自己的结果及其流程规定的审核/验收；任务树仅组织责任与依赖，不是自动执行调度器。项目可选，任务不以项目创建为前提。普通聊天与正式目标/计划分开，引用材料不会自动授权读取。版本恢复产生新变更，不回滚外部副作用。
