# M02：独立接入与剩余契约

本页为 M02 设计基线；存储/身份/安全命令由 [M03](m03-storage.md) 实现，执行/停止证明/流程由 [M05](m05-workflow.md) 本地实现，真实 Harness 适配属 M06。Taskloom 定义自己的业务协议，后续由 Harness 新增插件适配。NEX/Buddy 的接口、凭据及停止能力不作为开发前置条件，也不据其源码推断真实接入通过。保留 PluginKit、AgentKit 合并语义及已有 Agent 运行时复用，不建设执行引擎。

## 变更与消费者

必要性：解除外部平台结构对本项目的约束，同时让执行安全与扩展步骤有可实现的边界。通用性：身份、执行代次、结果及停止证据不依赖特定 Agent 产品。兼容性：以下为首版契约，后续变更必须版本化。受影响消费者为 HTTP 认证/API、授权、执行命令、flow/State、SQL 仓储及未来 Harness 适配插件。公共 Go DTO 随 M03—M05 的真实消费者逐项实现，不生成空壳接口。

## 身份和权限

首版使用 `identity/local`，唯一 Deps 为 `store: identity.CredentialLookup`，由 SQL 提供；公开 Authenticate 与 Directory.Resolve/Validate。租户、人、Agent、运行实例分别有不可变 ID；实例每次启动有独立 incarnation，凭据绑定租户/主体/实例及有效期。负责人关系不隐含代理授权，客户端请求体不能指定可信操作者。

由受控管理员初始化入口建立首个人和显式授权；随后受权管理员登记 Agent/实例、签发可撤销的高熵不透明凭据。秘密只在签发时返回，服务端仅存摘要及元数据，日志不得记录秘密。逐请求核验主体、凭据有效期和撤销状态；正式写入在事务提交前核验本地授权版本并与撤销串行化。已有请求先提交则有效，撤销先提交则拒绝；不承诺追回已发生的外部副作用。实例停止证明凭据与模型可调用的业务凭据分离。

权限采用有效租户成员、固定管理员/成员角色、任务负责人和参与关系；不提供 Scope/Grant、通配符、可配置动作目录或逐动作授权 API。业务命令按明确规则检查，具体见[成员与任务权限](permissions.md)。浏览器会话仍使用服务端可撤销会话与 HttpOnly/SameSite Cookie，生产 HTTPS 启用 Secure；Agent 归属不继承权限。

## 共用业务协议与 Harness 责任

通过现有共用 API 模块提供命名操作：读取任务/消息、认领与保活执行、提交回复、请求停止、报告执行结束及停止证据。人和 Agent 使用同一授权模型；没有 agent 专用业务副本。HTTP 路由和完整字段 schema 随 M04/M05 实现固定，不借 M02 声称可联调。

写命令带幂等键和 expectedVersion；涉及工作依据的操作带 roundId、basisVersion，执行写入另带 executionId/generation。租户和 actor 来自认证。相同操作/主体/幂等键与相同载荷返回已保存结果；同键不同载荷冲突。无权限返回 403，版本/代次/幂等冲突返回 409，格式错误返回 400；流程等待是带原因的业务结果，不是技术失败。提交的回复即使后续审核不通过也保留；事务技术失败则回复、交付、审计和事件全部回滚。

示意请求（非已实现端点）：

```json
{"operation":"reply.submit","idempotencyKey":"request-1","expectedVersion":12,"taskId":"task-1","roundId":"round-1","basisVersion":3,"executionId":"exec-1","generation":2,"body":"交付结果"}
```

Harness 插件负责认证、授权变化流订阅/游标恢复、认领后启动运行、保活、处理新消息和输入、显式提交结果、停止与可靠上报。事件可以重复；Ack 只代表收到，断线和在线均不证明运行状态。重连不能自动新建执行；先读取当前执行、代次及停止请求。快照与游标衔接、过期重同步沿用通信契约；任务系统不负责 steer、上下文或工具清理。

## 停止证据与可信边界

停止请求原子保存 stopRequestId、executionId、generation、instanceId/incarnation，失效旧写入资格并发 outbox；请求已发送/已接收、超时、租约过期、Agent 文本“已停止”均不是停止证明。普通 EndExecution 只报告主运行结束，不能默认证明子进程或外部工作已结束。

可信实例凭据可提交结构化证据：上述完整绑定、evidenceId、主运行结束状态、受管子进程清理状态、已登记外部工作清单及各自结束/隔离依据。服务端验证绑定和能力版本，并保存来源、接收时间、摘要及审计；声明能力本身不构成证据。不接收模型业务凭据伪造的清理回执。允许受限提交旧代次的待处理停止证据，但只能关闭对应旧执行，不能提交结果或改变当前执行；已撤销凭据始终拒绝。

| 观察 | 解释与允许动作 |
|---|---|
| requested / acknowledged | 已请求/收到；继续等待，不释放安全门 |
| 主运行结束，子进程或外部工作未知 | 保存局部证据，保持 unknown/待恢复 |
| 主运行及其全部受管工作结束，外部工作已结束或有明确隔离依据 | 该执行可安全退出；flow 仍检查其余完成条件 |
| 回执错实例/错停止请求/内容冲突 | 拒绝；不能覆盖既有证据 |
| 无法再取证 | 受权管理员走独立恢复命令，记录证据、隔离措施与风险；不能伪造自动停止成功 |

自然结束沿同一证据规则关闭执行，不要求先产生取消请求；此时绑定服务端执行记录及终结标识。收到停止请求后的回执必须绑定该请求。新执行/重开/替换以及要求安全收尾的任务完成，均检查仍未关闭的相关旧执行。隔离只覆盖有证据的范围，不承诺任意远端工具副作用被撤销或恰好一次。可信运行时说谎或未登记的外部工作无法由 Taskloom 自行证明；真实适配验收必须验证受管工作覆盖范围。

## State 幂等、认领和文件

Enter 幂等键由 EntryID、RoundID 以及步骤实际依赖的依据版本、候选交付修订、策略版本、前序证据版本构成；不要使用 Enter 自己写入后必变的 TaskVersion 造成重复循环。同键重复不得重复记录或 outbox；证据变化产生新记录并保留旧依据。检查只读，Enter 仅本地事务写入。重新提交后，同事务同步已到达步骤的新证据并重查；未来步骤不得提前 Enter，前序失效保留当前位置和等待原因。

认领命令在同一事务锁定任务协调行、校验 expectedVersion/当前依据、调用 CheckAction(OpenExecution) 重查已到达步骤与当前进入条件，再建立执行代次；不得在事务外检查后直接写入。State 不反向依赖 flow，CheckAction 不变成通用动作执行器。

F02：文件版commit 时间线通过材料 ReferenceKeeper 固定 fileId/version，校验租户、任务读写范围、上传完成和保留状态；交付引用同事务固定commit及文件版本。链接只存地址，不冒充快照。删除与引用竞争以 SQL 锁/引用记录串行化，S3 删除走 outbox 和补偿；具体实现及真实存储验证归 M07。

## 存储、迁移与流程定义

SQL 存储采用 GORM，不绑定 PostgreSQL。本地开发和自动验证默认使用 SQLite；生产按配置选择已适配的 SQL 驱动与 DSN，不修改业务插件。首批适配目标为 SQLite、MySQL、PostgreSQL，其他 GORM 驱动按需接入并验证，不把 ORM 的支持列表直接等同于项目已验证的数据库列表。

GORM 留在 storage/sql 仓储实现内部，cap/domain/State 不暴露 `*gorm.DB` 或方言类型；各模块拥有自身表、仓储和迁移，SQL 插件提供同一 UnitOfWork。跨仓储操作必须使用该事务关联的 GORM commit 时间线，不能退回根连接自动提交。新增步骤可以带自己的仓储，但不能自行提交或使用另一数据库冒充原子性。

连接配置为 `driver` + `dsn`：本地默认 driver=sqlite；同驱动换实例只改 DSN，跨数据库类型同时修改 driver。原生 DSN 格式不同，不能假设 GORM 自动识别驱动。保持两层配置，不增加连接解析框架或为每个方言新增业务插件；未知/未编入的驱动启动时报错，DSN 不写入日志。具体部署见[配置契约](configuration.md)。

并发安全以版本条件更新、唯一约束和同事务事实为基础。文档中的“锁任务协调行”表示串行化要求，不要求所有方言执行相同的 SELECT FOR UPDATE；SQLite 写事务串行化及忙重试、生产数据库锁/冲突重试由存储适配落实。重试仅覆盖完整本地事务，不夹带远端副作用。时间、JSON、索引及错误归一化由仓储适配处理，禁止业务插件依赖某数据库专有类型或 SQL。迁移互斥同样由适配实现，不绑定 PostgreSQL advisory lock。

M03 用真实 SQLite 文件数据库验证持久化、跨仓储回滚、并发幂等、版本冲突、撤销和 outbox；测试连接显式启用外键约束，临时数据库隔离，避免不同连接误连不同内存库。生产启用某方言前，在该数据库上运行同一仓储/事务/迁移契约测试，尤其是并发与失败恢复；SQLite 通过不代表所有生产数据库通过。切换连接不会自动搬迁已有业务数据。

依据：[GORM 连接文档](https://gorm.io/docs/connecting_to_the_database.html)按驱动分别初始化连接；[迁移文档](https://gorm.io/docs/migration.html)说明统一 Migrator 仍需处理数据库差异。AutoMigrate 可用于受控版本迁移中的建表操作，不替代模块版本、校验和与升级记录。

F07：迁移由已装配模块显式提交模块 ID、版本、校验和及依赖清单给 SQL 资源 owner；不用目录扫描或新 registry。启动服务前在独占迁移锁下检查顺序、重复、缺失依赖和已应用校验和，失败不开放业务流量；破坏性迁移单独部署，不在构造函数中执行。领域逻辑不能直接访问其他领域表。M03 验证迁移失败恢复及跨仓储回滚，M05 验证新增 State 的独立表与配置装配。

通用 runtime/config 只管两层合并与 PluginKit 构建，不认识 task/catalog、FlowRef 或状态种类。未来流程目录 owner 验证所有挂载定义及内联 State、重复 ID/版本、默认引用及历史定义兼容；同版本内容变化拒绝启动/发布，缺失旧任务定义拒绝服务旧任务并明确故障。未实现的可达 kind 仍由 PluginKit 拒绝。移除旧检查不代表新流程校验已实现。

## 验收边界

M02 交付本契约、插件依赖同步及加载器回归；此处不声称身份、停止、数据库或真实 Agent 可用。M03 验证凭据撤销/跨租户/幂等事务与迁移；M04/M05 验证 DTO、路由、状态重查、旧代次拒绝及部分停止证据不放行；M06 由真实 Harness 插件覆盖运行/子进程/外部工作、断线恢复、取消与升级。模拟客户端可以测试协议拒绝条件，不能代替真实运行停止证据。M02 不再等待 NEX/Buddy 环境。
