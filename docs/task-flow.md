# 任务流程

流程不再是可组合的状态机。任务系统只存储它能直接核实的事实，"现在在哪一步、在等什么"每次读取时从这些事实计算，不落库，因此不会与事实漂移。实现见 `plugins/flow`（`task/flow`），接口见 `cap/flow`；不变量见[核心契约](core-contracts.md)，HTTP 路径见 [API](api.md#执行交付与验收)。

## 存什么

| 存储字段 | 语义 |
| --- | --- |
| Status | active / cancelled / completed，只由流程控制器写入 |
| RoundID | 一轮工作；Restart（退回或重开）新建轮次，正常推进不变 |
| Acceptance | `manual` 或 `none`，创建任务时按部署配置写入，此后固定；部署配置变更不暗改旧任务 |

缺少 Acceptance 的旧位置记录被明确拒绝（冲突），不猜测其验收方式。

## 推导什么

`State` 与 `Waiting` 按以下顺序由事实计算，第一个不满足的条件决定步骤和等待原因：

| 条件 | State | Waiting |
| --- | --- | --- |
| 目标或验收标准为空 | ready | 请补充任务目标 / 验收标准 |
| 本轮没有当前交付 | executing | 等待有效结果提交 |
| 当前交付的依据版本 ≠ 任务依据版本 | executing | 结果依据已失效 |
| manual 且当前交付没有负责人结论 | accepting | 等待负责人验收 |
| manual 且结论为退回 | accepting | 验收未通过，等待重新提交 |
| 本轮有未回答问题 | 保持上一行步骤 | 等待被提问人回答问题 |

全部满足即达成完成条件。终态 completed 的 State 为 completed；cancelled 保留推导出的步骤，Waiting 为"任务已取消"。

"待验收"不存记录：有当前交付、需要验收且无结论即为 pending，查询时合成。负责人的结论是一条引用结果 commit 的 `review.approved` / `review.rejected` commit，取最新一条；新交付或依据变化使旧结论自然不再适用。

## 控制器

| 方法 | 语义 |
| --- | --- |
| Initialize | 同事务创建位置：新 RoundID、active、当前配置的 Acceptance |
| Read | 读存储字段并推导步骤 |
| Refresh | 每个改变事实的命令在同事务末尾调用；达成完成条件即写 completed |
| CheckOpen | 分配和认领的前提：任务 active 且依据完整（非 ready） |
| Cancel | active → cancelled |
| Restart | 任何阶段 → 新轮 active，然后 Refresh；活跃任务即退回，终态即重开 |

取消、退回、重开和转交由命令模块同事务失效执行写资格（Writable），控制器不观察外部进程。完成不等待执行者停下。

活跃任务的依据随时可改，不设"执行中禁止修改"关卡：依据版本变化后，旧依据上的执行不能再提交，旧依据上的结果不再计为有效结果（推导回 executing），执行者按新依据重新认领。

## 命令各自固定什么

客户端不传流程版本。每个命令只带它真正需要固定的对象，其余由服务端事实校验：

| 命令 | 客户端固定 | 服务端校验 |
| --- | --- | --- |
| Open | BasisVersion | 依据完整、已分配、凭据；同一凭据同依据已有执行时冲突（人在分配时即开始） |
| Submit | ExecutionID | 执行可写、轮次与依据版本仍为当前 |
| Review | SubmissionID + CommitID | 仍为当前交付且依据未变 |
| Restart / Ask | RoundID | 仍为当前轮 |
| Assign / Cancel | 无 | 阶段与授权 |

## 分配、认领与转交

- 负责人或管理员可把任务分配给有效用户或 Agent；分配同事务加入参与关系并失效当前执行。
- 分配给人即开始：同事务建立人工执行（Manual），不绑定凭据。依据变更后，人可再用 Open 按新依据重新开始。
- Agent 须用 Open 认领：执行绑定所用凭据。同一凭据在本轮、本依据已有可写执行时不能重复认领（直接继续）；换凭据（如重启后的新实例）认领会失效旧执行。两个并发认领最多一个成功。
- 仍参与任务的当前人工处理人可以转交给他人或 Agent；普通参与者和 Agent 不能转交。转交失效原执行，原处理人保留参与关系、不保留分配权；负责人和验收人不变。
- 执行记录最近进展时间（认领、本人留言、提问、提交），只供判断是否介入，不改变流程，也没有后台扫描。

## 问题与人工引导

- 人可以随时在时间线给处理人留言；留言不算交付，也不改变依据。正式改要求直接修改依据（见上）。
- 任务参与者需要输入时提问：问题正文是 question commit，问题记录只保存轮次、提问人、被提问人、状态和回答引用。被提问人默认是负责人，也可指定一位当前参与者（有效成员，不能是自己）。
- 未回答的问题让快照 `NextActor=addressee` 并进入被提问人的收件箱，同时阻止任务完成（Agent 仍可继续执行、提交、被验收）。只有被提问人能回答当前轮的问题，回答是引用问题的 answer commit，重复回答冲突。旧轮或终态任务的问题不再显示也不可回答。

## 扩展方式

需要新的完成条件时，在推导函数中加一行有真实消费者的事实检查，而不是预建状态插件接口。若将来确有多个互斥流程，再按真实需求引入，届时同样遵守"只存事实、步骤推导"的原则。
